1.3 Tokens, embeddings, and weights

From this section on, you rebuild SmolLM2-135M-Instruct piece by piece. A model on Hugging Face is two things: a configuration that gives its sizes, and a checkpoint that holds its trained weights. This section loads both, then builds the model’s first layer, the token embedding.

Read it as: 30 identical layers (num_hidden_layers), each working on vectors of 576 numbers (hidden_size). Attention uses 9 query heads but only 3 key/value heads, so each head has 576 / 9 = 64 dimensions; Section 1.5 explains why the counts differ. LlamaForCausalLM is the architecture the code must implement.

A small dataclass keeps these fields typed. The field names match Hugging Face’s, so you can compare against any Llama-family config.json.

from __future__ import annotations

import json
from dataclasses import dataclass, fields
from pathlib import Path

from huggingface_hub import hf_hub_download

MODEL_ID = "HuggingFaceTB/SmolLM2-135M-Instruct"


@dataclass(frozen=True)
class LlamaConfig:
    """The sizes of a Llama-family model, as in its ``config.json``."""

    vocab_size: int = 49152
    hidden_size: int = 576
    intermediate_size: int = 1536
    num_hidden_layers: int = 30
    num_attention_heads: int = 9
    num_key_value_heads: int = 3
    rope_theta: float = 100000.0
    rms_norm_eps: float = 1e-5
    max_position_embeddings: int = 8192
    tie_word_embeddings: bool = True
    eos_token_id: int = 2
    head_dim: int = 0  # 0 means hidden_size // num_attention_heads

    def __post_init__(self) -> None:
        if (
            not self.head_dim
        ):  # newer configs, such as Qwen3's, give it explicitly
            object.__setattr__(
                self, "head_dim", self.hidden_size // self.num_attention_heads
            )

    @classmethod
    def from_pretrained(cls, model_id: str = MODEL_ID) -> LlamaConfig:
        """Reads the config of a Hugging Face model."""
        raw = json.loads(
            Path(hf_hub_download(model_id, "config.json")).read_text()
        )
        return cls(
            **{f.name: raw[f.name] for f in fields(cls) if f.name in raw}
        )

    if "embed_tokens" in name:
        return "embedding"
    if "self_attn" in name:
        return "attention"
    if "mlp" in name:
        return "MLP"
    return "norms"

  • Memory is parameters times bytes per parameter. The checkpoint stores bfloat16 (2 bytes); this book converts to float32 (4 bytes), so its results can be compared exactly with reference implementations. The handbook’s GPU memory calculation applies the same arithmetic to large models, plus the KV cache you build in Section 1.8.
  • There is no lm_head.weight. With tie_word_embeddings, the output layer reuses the embedding matrix; Section 1.6 uses that.

The loader below maps the file into memory and returns NumPy arrays. NumPy has no bfloat16 type, but the conversion is exact and cheap: a bfloat16 value is the upper 16 bits of a float32, so shifting the bits left by 16 gives the same number as a float32. MAX modules accept NumPy arrays directly, so this is all the loading code the model needs.

from __future__ import annotations

import json

import numpy as np
from huggingface_hub import hf_hub_download

from minillm.config import MODEL_ID

_NUMPY_DTYPES = {
    "F32": np.float32,
    "F16": np.float16,
    "I64": np.int64,
    "I32": np.int32,
}


def read_safetensors(path: str) -> dict[str, np.ndarray]:
    """Reads a safetensors file, converting floating-point tensors to float32."""
    with open(path, "rb") as f:
        header_len = int.from_bytes(f.read(8), "little")
        header = json.loads(f.read(header_len))
    data = np.memmap(path, dtype=np.uint8, mode="r", offset=8 + header_len)
    tensors = {}
    for name, info in header.items():
        if name == "__metadata__":
            continue
        start, end = info["data_offsets"]
        raw = data[start:end]
        if info["dtype"] == "BF16":
            array = (raw.view(np.uint16).astype(np.uint32) << 16).view(
                np.float32
            )
        else:
            array = raw.view(_NUMPY_DTYPES[info["dtype"]])
            if array.dtype == np.float16:
                array = array.astype(np.float32)
        tensors[name] = array.reshape(info["shape"])
    return tensors


def load_checkpoint(model_id: str = MODEL_ID) -> dict[str, np.ndarray]:
    """Downloads a model's safetensors checkpoint and returns its tensors."""
    return read_safetensors(hf_hub_download(model_id, "model.safetensors"))

Token embeddings

The model’s first layer turns each token ID into a vector of 576 numbers. It is a lookup table: row i of a [49152, 576] matrix is the vector for token i. max.nn.Embedding implements it. load_state_dict replaces its random weight with the checkpoint’s:

with default_device(DEVICE), default_dtype(DType.float32):
    embed = Embedding(config.vocab_size, dim=config.hidden_size)
embed.load_state_dict({"weight": weights["model.embed_tokens.weight"]})

tokenizer = AutoTokenizer(MODEL_ID)
ids = tokenizer([" Paris France banana"])["input_ids"][0]
vectors = embed(Tensor(np.array([ids]), device=DEVICE))
print(ids, [tokenizer.decode([i]) for i in ids])
print(vectors.shape)

Training places related tokens near each other. Cosine similarity, the cosine of the angle between two vectors, shows it even before any layer runs:

\[\cos\theta = \frac{a \cdot b}{\lVert a \rVert \, \lVert b \rVert}\]

It is 1 for vectors pointing the same way, 0 for unrelated (orthogonal) ones, and \(-1\) for opposite ones, whatever their lengths.

def cosine(a: np.ndarray, b: np.ndarray) -> float:
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))


print(f"Paris  ~ France: {cosine(v[0], v[1]):.2f}")
print(f"Paris  ~ banana: {cosine(v[0], v[2]):.2f}")
print(f"France ~ banana: {cosine(v[1], v[2]):.2f}")

Paris  ~ France: 0.59
Paris  ~ banana: 0.36
France ~ banana: 0.37

The groups separate without the model ever being told what a country or a fruit is: words used in similar contexts during training end up with similar vectors.

The 30 layers you build next refine these vectors using context: what Paris means depends on the tokens around it.
