1.4 Building blocks

Each of SmolLM2’s 30 layers has the same structure:

x = x + attention(rms_norm(x))     # mix information across positions
x = x + mlp(rms_norm(x))           # transform each position on its own

This section builds the three pieces besides attention: RMSNorm, the SwiGLU MLP, and rotary position embeddings (RoPE), which attention uses to know where each token is. Each piece is a few lines with max.nn and max.functional, and each is checked against a NumPy version of its formula, using the real weights of layer 0.

A layer’s weights are the checkpoint entries under its name prefix. This helper selects them and strips the prefix, so a module can load them with load_state_dict:

def select(
    weights: dict[str, np.ndarray], prefix: str
) -> dict[str, np.ndarray]:
    """Returns the entries under ``prefix``, with the prefix removed."""
    return {
        name.removeprefix(prefix): value
        for name, value in weights.items()
        if name.startswith(prefix)
    }

A random input stands in for the hidden states that reach layer 0. to_np reads a tensor back, and compare reports the largest difference from the NumPy result, absolute and relative to the largest value:

rng = np.random.default_rng(0)

x = Tensor(x_np, device=DEVICE)


def to_np(t: Tensor) -> np.ndarray:
    return t.to_numpy()


def compare(actual: np.ndarray, expected: np.ndarray) -> None:
    diff = np.abs(actual - expected).max()
    relative = diff / np.abs(expected).max()
    print(f"max difference {diff:.1e} (relative {relative:.1e})")
    assert relative < 1e-4, "doesn't match the NumPy reference"

RMSNorm

Deep networks train better when each layer sees inputs of a stable scale. RMSNorm divides each vector by its root mean square, then multiplies by a learned weight per dimension:

\[\mathrm{RMSNorm}(x) = \frac{x}{\sqrt{\mathrm{mean}(x^2) + \epsilon}} \cdot w\]

Unlike LayerNorm, it doesn’t subtract the mean or add a bias, which saves work and in practice trains as well. max.nn.RMSNorm implements it:

with default_device(DEVICE), default_dtype(DType.float32):
    norm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
norm.load_state_dict(select(weights, "model.layers.0.input_layernorm."))

w = to_np(norm.weight)
expected = (
    x_np / np.sqrt((x_np**2).mean(-1, keepdims=True) + config.rms_norm_eps) * w
)
compare(to_np(norm(x)), expected)

max difference 3.0e-08 (relative 7.7e-08)

The learned weight is far from the all-ones it starts as. In layer 0, most dimensions are scaled close to zero, a few stand out several times larger, and nearly half are negative, so the norm also flips their sign. Hover over a bar to read its value:

The SwiGLU MLP

The MLP transforms each position independently. SmolLM2 uses a gated variant: one projection, passed through SiLU, decides how much of a second projection to let through, and a third projection maps back to the hidden size:

\[\mathrm{MLP}(x) = W_{\text{down}}\,\big(\mathrm{SiLU}(W_{\text{gate}}\,x) \odot W_{\text{up}}\,x\big)\]

where \(\mathrm{SiLU}(z) = z \cdot \sigma(z)\). The attribute names match the checkpoint (gate_proj, up_proj, down_proj), so load_state_dict needs no renaming.

z = np.linspace(-6, 6, 241)

from __future__ import annotations

from max import functional as F
from max.driver import Device
from max.dtype import DType
from max.graph import Dim
from max.nn import Linear, Module
from max.tensor import Tensor
from max.tensor.sharding import DeviceMesh

from minillm.config import LlamaConfig


class MLP(Module):
    """The SwiGLU feed-forward network of a Llama layer."""

    def __init__(self, config: LlamaConfig) -> None:
        hidden, inner = config.hidden_size, config.intermediate_size
        self.gate_proj = Linear(hidden, inner, bias=False)
        self.up_proj = Linear(hidden, inner, bias=False)
        self.down_proj = Linear(inner, hidden, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        return self.down_proj(F.silu(self.gate_proj(x)) * self.up_proj(x))

Saved to minillm/layers.py.

with F.lazy(), default_device(DEVICE), default_dtype(DType.float32):
    mlp = MLP(config)
mlp.load_state_dict(select(weights, "model.layers.0.mlp."))

gate, up, down = (
    to_np(getattr(mlp, n).weight) for n in ("gate_proj", "up_proj", "down_proj")
)
g = x_np @ gate.T
expected = (g / (1 + np.exp(-g)) * (x_np @ up.T)) @ down.T
compare(to_np(mlp(x)), expected)

max difference 1.0e-03 (relative 8.2e-07)

Linear stores its weight as [out_features, in_features], the same layout as PyTorch, so the NumPy version multiplies by the transpose. The differences, about one part in a million, come from summing thousands of float32 products in a different order than NumPy does.

Rotary position embeddings

Attention compares tokens with dot products, which by themselves ignore order: “dog bites man” and “man bites dog” contain the same tokens. The model needs to know positions.

RoPE encodes position by rotating query and key vectors. It splits each 64-dimension head vector into 32 pairs and rotates pair i at position p by the angle \(p \cdot \theta_i\), where \(\theta_i = \text{base}^{-2i/d}\). Early pairs rotate quickly and late pairs slowly, like the hands of a clock. SmolLM2’s base is rope_theta = 100000.

Following the Hugging Face layout, the two halves of the vector form the pairs: element i pairs with element i + 32. Rotating every pair at once is then two multiplications:

\[\mathrm{rope}(x) = x \cdot \cos + \mathrm{rotate\_half}(x) \cdot \sin, \qquad \mathrm{rotate\_half}([x_1, x_2]) = [-x_2, x_1]\]

start offsets the positions; Section 1.8 needs it for the KV cache. The tables name their dtype: a Tensor built without one takes the device’s default, which is bfloat16 on a GPU, and bfloat16 can’t even represent every integer position above 256 exactly. Lengths are typed int | Dim because a compiled model sees symbolic dimensions such as seq_len instead of numbers; Section 1.2 shows where they come from.

def rope_cos_sin(
    head_dim: int,
    theta: float,
    start: int | Dim | Tensor,
    length: int | Dim,
    device: Device | DeviceMesh,
) -> tuple[Tensor, Tensor]:
    """Returns the RoPE cos and sin tables, ``[length, head_dim]``, for
    positions ``start`` to ``start + length - 1``."""
    inv_freq = Tensor(
        [theta ** (-i / head_dim) for i in range(0, head_dim, 2)],
        dtype=DType.float32,
        device=device,
    )
    positions = (
        Tensor.arange(length, dtype=DType.float32, device=device) + start
    )
    angles = F.outer(positions, inv_freq)
    angles = F.concat([angles, angles], axis=-1)
    return F.cos(angles), F.sin(angles)


def rotate_half(x: Tensor) -> Tensor:
    half = x.shape[-1] // 2
    return F.concat([-x[..., half:], x[..., :half]], axis=-1)


def apply_rope(x: Tensor, cos: Tensor, sin: Tensor) -> Tensor:
    """Rotates ``x``, shaped ``[batch, seq, heads, head_dim]``."""
    seq, dim = cos.shape
    cos = cos.reshape([1, seq, 1, dim])
    sin = sin.reshape([1, seq, 1, dim])
    return x * cos + rotate_half(x) * sin

RoPE relies on two properties, and both are easy to check. First, a rotation doesn’t change a vector’s length:

q = Tensor(
    rng.standard_normal((1, 8, 1, config.head_dim)).astype(np.float32),
    device=DEVICE,
)
cos, sin = rope_cos_sin(config.head_dim, config.rope_theta, 0, 8, DEVICE)
rotated = to_np(apply_rope(q, cos, sin))
print(np.linalg.norm(to_np(q), axis=-1).ravel()[:4])
print(np.linalg.norm(rotated, axis=-1).ravel()[:4])
assert np.allclose(
    np.linalg.norm(to_np(q), axis=-1),
    np.linalg.norm(rotated, axis=-1),
    rtol=1e-5,
)

[6.897215  6.9866242 7.8358827 6.884518 ]
[6.897215  6.9866247 7.8358827 6.884518 ]

Second, the dot product of a rotated query and key depends only on how far apart they are. Here a query at position 7 and a key at position 3 score the same as at positions 107 and 103:

def score(q_pos: int, k_pos: int) -> float:
    qv = Tensor(np.ones((1, 1, 1, config.head_dim), np.float32), device=DEVICE)
    kv = Tensor(
        np.linspace(-1, 1, config.head_dim, dtype=np.float32).reshape(
            1, 1, 1, -1
        ),
        device=DEVICE,
    )
    q_rot = apply_rope(
        qv, *rope_cos_sin(config.head_dim, config.rope_theta, q_pos, 1, DEVICE)
    )
    k_rot = apply_rope(
        kv, *rope_cos_sin(config.head_dim, config.rope_theta, k_pos, 1, DEVICE)
    )
    return float((to_np(q_rot) * to_np(k_rot)).sum())


print(f"{score(7, 3):.4f}  {score(107, 103):.4f}  {score(7, 5):.4f}")
assert (
    abs(score(7, 3) - score(107, 103)) < 1e-3
    and abs(score(7, 3) - score(7, 5)) > 1e-2
)

10.2645  10.2645  7.8206

The first two scores match. The third, for positions two apart instead of four, differs. The sweep below fixes the key at position 10 or at 110 and moves the query up to 48 positions after it. The two curves lie on top of each other:

q_vec = np.ones(config.head_dim, np.float32)
k_vec = np.linspace(-1, 1, config.head_dim, dtype=np.float32)
cos_t, sin_t = (
    to_np(t)
    for t in rope_cos_sin(config.head_dim, config.rope_theta, 0, 160, DEVICE)
)


def rope_np(v: np.ndarray, pos: int) -> np.ndarray:
    half = len(v) // 2
    return v * cos_t[pos] + np.concatenate([-v[half:], v[:half]]) * sin_t[pos]


distances = np.arange(49)
fig = go.Figure(
    [
        go.Scatter(
            x=distances,
            y=[
                rope_np(q_vec, k_pos + d) @ rope_np(k_vec, k_pos)
                for d in distances
            ],
            name=f"key at position {k_pos}",

            hovertemplate="distance %{x}: %{y:.3f}<extra></extra>",
        )

            (10, viz.BLUE, "solid", 5),

)

Because scores depend only on relative position, RoPE generalizes well, and most open models use it.
