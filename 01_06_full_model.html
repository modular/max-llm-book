1.6 The full model

You now have every part of SmolLM2. This section assembles them into a decoder layer, stacks 30 layers into the model, adds the output head, loads all 272 weights, and compiles the result. Then it checks that your model’s logits match MAX’s own implementation of SmolLM2, the one AutoModel loads.

The decoder layer

A layer normalizes its input, runs attention, and adds the result back to the input; then it does the same with the MLP:

\[\begin{aligned} h &= x + \mathrm{Attention}(\mathrm{RMSNorm}(x)) \\ x’ &= h + \mathrm{MLP}(\mathrm{RMSNorm}(h)) \end{aligned}\]

Adding back (the residual connection) means each layer only refines the hidden state instead of replacing it, which helps a stack of 30 layers train well.

The attribute names match the checkpoint once more, so a layer loads model.layers.N.* directly.

from __future__ import annotations

from max import functional as F
from max.driver import Device
from max.dtype import DType
from max.nn import Embedding, Linear, Module, ModuleList, RMSNorm
from max.tensor import Tensor, default_device, default_dtype
from numpy.typing import NDArray

from minillm.attention import Attention
from minillm.config import LlamaConfig
from minillm.layers import MLP


class DecoderLayer(Module):
    """One transformer layer: attention and an MLP, each with a residual."""

    def __init__(self, config: LlamaConfig) -> None:
        eps = config.rms_norm_eps
        self.input_layernorm = RMSNorm(config.hidden_size, eps=eps)
        self.self_attn = Attention(config)
        self.post_attention_layernorm = RMSNorm(config.hidden_size, eps=eps)
        self.mlp = MLP(config)

    def forward(self, x: Tensor) -> Tensor:
        x = x + self.self_attn(self.input_layernorm(x))
        return x + self.mlp(self.post_attention_layernorm(x))

The update is 10 to 30 times larger than the input, because embeddings start as small vectors. The residual sum still carries the original embedding forward. Later in this section, a plot follows this residual stream through all 30 layers.

The model

The model embeds the tokens, runs the 30 layers in order, and normalizes the result. The causal LM wrapper adds lm_head, a Linear from 576 dimensions to one logit per vocabulary entry. The module tree mirrors Hugging Face’s LlamaForCausalLM, so every checkpoint name is also a parameter name.

load_model builds the model inside F.lazy(), so the random initialization never runs, and then loads the weights. SmolLM2 ties lm_head to the embedding table, so the loader uses the same array for both.

class LlamaModel(Module):
    """The embedding, the decoder layers, and the final norm."""

    def __init__(self, config: LlamaConfig) -> None:
        self.embed_tokens = Embedding(config.vocab_size, dim=config.hidden_size)
        self.layers = ModuleList(
            [DecoderLayer(config) for _ in range(config.num_hidden_layers)]
        )
        self.norm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)

    def forward(self, input_ids: Tensor) -> Tensor:
        x = self.embed_tokens(input_ids)
        for layer in self.layers:
            x = layer(x)
        return self.norm(x)


class LlamaForCausalLM(Module):
    """A Llama model with its language-model head: token IDs in, logits out."""

    def __init__(self, config: LlamaConfig) -> None:
        self.model = LlamaModel(config)
        self.lm_head = Linear(config.hidden_size, config.vocab_size, bias=False)

    def forward(self, input_ids: Tensor) -> Tensor:
        return self.lm_head(self.model(input_ids))


def load_model(
    config: LlamaConfig,
    weights: dict[str, NDArray],
    device: Device,
    model_class: type[Module] = LlamaForCausalLM,
) -> Module:
    """Builds ``model_class`` on ``device`` and loads ``weights`` into it."""
    with F.lazy(), default_device(device), default_dtype(DType.float32):
        model = model_class(config)
    if config.tie_word_embeddings:
        weights = {
            **weights,
            "lm_head.weight": weights["model.embed_tokens.weight"],
        }
    model.load_state_dict(weights)
    return model

That is 28M more than the checkpoint’s 134.5M because lm_head counts as its own 49152 × 576 parameter, loaded from the same array as the embedding table. load_state_dict is strict: a missing or misnamed weight raises an error instead of silently keeping a random value, so a successful load already proves the names line up.

The first token behaves differently. Its state jumps to about 24,000 at layer 12, over a hundred times the other tokens’ (about 120 to 165), and stays there until it drops in the last two layers. Models use the first position as a resting place for attention (Section 1.5), and this large state is part of how they do it.

Every layer writes into the same stream, so you can ask what the model would predict if it stopped early: apply the final norm and lm_head to each layer’s output. For the hidden state \(h_\ell\) after layer \(\ell\), the logit lens reads

\[p_\ell = \mathrm{softmax}\big(E \, \mathrm{RMSNorm}(h_\ell)\big)\]

where \(E\) is the embedding table that lm_head shares. Apply it at every position and after every layer:

final_norm = weights["model.norm.weight"]
table = weights["model.embed_tokens.weight"]  # lm_head shares it
normed = (
    states
    / np.sqrt((states**2).mean(-1, keepdims=True) + config.rms_norm_eps)
    * final_norm
)
lens = normed @ table.T  # [layer + 1, token, vocab]
lens_probs = np.exp(lens - lens.max(-1, keepdims=True))
lens_probs /= lens_probs.sum(-1, keepdims=True)

positions = np.arange(len(ids))
final_top = lens[-1].argmax(-1)  # each position's prediction after layer 30
p_final = lens_probs[:, positions, final_top]  # [layer + 1, token]
paris = tokenizer([" Paris"])["input_ids"][0][0]
assert final_top[-1] == paris

Compile

Running 30 layers eagerly works but executes hundreds of operations one at a time. Compiling turns the whole forward pass into one optimized graph. The input is a batch of token-ID sequences of any length:

start = time.perf_counter()
compiled = model.compile(
    TensorType(DType.int64, ("batch", "seq_len"), device=DEVICE)
)
print(f"compiled in {time.perf_counter() - start:.0f} s")

start = time.perf_counter()
logits = compiled(Tensor(np.array([ids]), device=DEVICE)).to_numpy()
print(
    f"forward pass: {(time.perf_counter() - start) * 1000:.0f} ms, logits {logits.shape}"
)

Check against MAX’s SmolLM2

AutoModel loads SmolLM2 with MAX’s own implementation of the architecture that config.json names LlamaForCausalLM, and can return the logits for each token it generates. The first generated token’s logits must match your model’s logits at the last prompt position:

    input_ids=[ids], max_new_tokens=1, output_logits=True

expected = reference.logits[0][0]
reference_model.close()

ours = logits[0, -1]
print(

In the run shown here, on an Apple-silicon Mac with a Metal GPU, the largest difference between your logits and MAX’s was about 4e-5, and both models predict the same next token. Treat these numbers as an example: yours depend on your hardware and vary from run to run. An error in any layer, such as a wrong RoPE layout or a missing scale, would change the logits by whole units, so the match shows that every layer you wrote is correct.

The same code runs the larger SmolLM2 models by changing MODEL_ID. Other Llama-family models need small additions: Llama 3.1, for example, rescales RoPE’s frequencies (rope_scaling in its config), and Qwen2 adds biases to the query, key, and value projections. The handbook’s Choosing the right model discusses how size, architecture, and license trade off when you pick one.
