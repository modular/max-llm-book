4.2 Verifying a model’s logits

Layer tests catch bugs in one layer. A whole model can still go wrong in ways no layer test sees: a weight loaded into the wrong layer, a tied head that isn’t tied, a mask that only fails on long prompts. So model bring-ups end with logit verification: run the same prompts through your model and a trusted reference, and compare the logits at every position.

This section verifies your SmolLM2 against Hugging Face’s PyTorch implementation, with the metrics MAX’s own verification tools use.

Prompts

Verification prompts should exercise different behavior: plain prose, code, numbers, another language, and a prompt long enough to stress attention and RoPE at larger positions.

long_prompt = " ".join(["The quick brown fox jumps over the lazy dog."] * 60)

def logits_pair(text: str) -> tuple[np.ndarray, np.ndarray]:
    ids = tokenizer([text])["input_ids"][0]
    mine = ours(Tensor(np.array([ids]), device=DEVICE)).to_numpy()[0]
    with torch.no_grad():
        theirs = reference(torch.tensor([ids])).logits[0].numpy()
    return mine, theirs

Metrics for logits

Logits feed a softmax, so on top of the elementwise metrics from Section 4.1, two measures matter for generation.

The KL divergence between the next-token distributions measures how much probability mass moved. It is the standard measure for comparing two models’ predictions, and it ignores differences in logits that softmax removes, such as a constant offset. For the reference distribution \(P\) and yours, \(Q\), at one position:

\[D_{\mathrm{KL}}(P \,\Vert\, Q) = \sum_i P_i \log \frac{P_i}{Q_i}\]

It is 0 only when the two distributions are identical.

Top-1 agreement is the fraction of positions at which both models predict the same most likely token. It is all that greedy decoding sees.

Show softmax, kl_divergence 26 lines 
def softmax(z: np.ndarray) -> np.ndarray:
    z = z.astype(np.float64) - z.max(-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(-1, keepdims=True)


def kl_divergence(p_logits: np.ndarray, q_logits: np.ndarray) -> float:
    """Mean KL(P || Q) over positions, in nats."""
    p, q = softmax(p_logits), softmax(q_logits)
    return float((p * (np.log(p + 1e-30) - np.log(q + 1e-30))).sum(-1).mean())


print(
    f"{'prompt':8} {'positions':>9} {'max err':>8} {'cos dist':>9} {'KL':>9} {'top-1':>6}"
)
errors = {}
for name, text in prompts.items():
    mine, theirs = logits_pair(text)
    errors[name] = np.abs(mine - theirs).max(-1)
    r = compare_outputs(mine, theirs, atol=1e-3, rtol=1e-3)
    top1 = (mine.argmax(-1) == theirs.argmax(-1)).mean()
    print(
        f"{name:8} {len(mine):>9} {r.max_abs_err:>8.1e} {r.cos_dist:>9.1e} "
        f"{kl_divergence(theirs, mine):>9.1e} {top1:>6.0%}"
    )
    assert top1 >= 0.99 and kl_divergence(theirs, mine) < 1e-6

Greedy generation

Matching logits at the prompt is necessary but not sufficient: generation feeds the model its own outputs, through your KV cache from Section 1.8. Compare 48 greedy tokens from your cached decoder with Hugging Face’s generate:

Show the code 27 lines 
cached = KVCacheDecoder(
    load_model(config, weights, DEVICE, CachedLlamaForCausalLM), config, DEVICE
)

gaps = {}
for name in ["prose", "code", "numbers"]:
    ids = tokenizer([prompts[name]])["input_ids"][0]
    mine = generate(cached, ids, 48, temperature=0)
    with torch.no_grad():
        out = reference.generate(
            torch.tensor([ids]),
            max_new_tokens=48,
            do_sample=False,
            output_logits=True,
            return_dict_in_generate=True,
        )
    theirs = out.sequences[0, len(ids) :].tolist()
    gaps[name] = [
        float(np.diff(np.sort(step[0].numpy())[-2:])[0]) for step in out.logits
    ]
    same = next(
        (i for i, (a, b) in enumerate(zip(mine, theirs)) if a != b), len(mine)
    )
    print(f"{name:8} identical for {same} of {len(mine)} tokens")
    assert same >= 24, (
        "diverged early; check the gap between the top two logits"
    )

A rounding difference can change the winner only at a step where the gap is smaller than the error, that is, where a line dips below the dotted one. Here the smallest gap is above 0.1 and the largest error about 1e-4, so no step comes close.

If a run does diverge after many tokens, the cause is usually a near tie: at some step two tokens have almost the same logit, and a difference in the fourth or fifth decimal place, from summing in a different order, picks a different winner. From then on the two texts differ, though both are valid greedy continuations. When you see a divergence, look at the gap between the top two logits at that step: a tiny gap means rounding, a large one means a bug.

Beyond logits: accuracy evaluations

Logit verification compares two implementations. It can’t tell you whether the model is good at a task, or whether a change that alters numbers on purpose, such as quantization, costs accuracy. For that, serving teams run task evaluations such as GSM8K or MMLU against the server (Section 7.1 serves your model). The handbook’s quantization page covers how quantized models are evaluated.
