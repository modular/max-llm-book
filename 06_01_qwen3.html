6.1 Qwen3: normalized queries and keys

Most open models are close relatives of the Llama architecture you built in Chapter 1. To bring up a new one, you find what changed and why. This section adds Qwen3, here the 0.6-billion-parameter model Qwen/Qwen3-0.6B. It subclasses your Llama classes, overrides only what differs, and verifies the result with the tools from Chapter 4.

Four differences matter:

  • A larger vocabulary, 151,936 tokens, which covers many languages and code. The embedding alone holds 156M parameters, about a quarter of the model’s 596M.
  • An explicit head_dim: 16 heads of 128 dimensions make 2048, wider than the 1024-dimension hidden state. q_proj projects up, and o_proj projects back down. The config class from Section 1.3 reads head_dim when a model sets it.
  • A larger RoPE base, 1,000,000, so the rotations turn more slowly and positions stay distinguishable over longer contexts.
  • QK-norm: an RMSNorm on every query and key head, before RoPE.

The first three are config values that your code already handles. QK-norm needs new code.

QK-norm

Attention scores are dot products of queries and keys. During training, nothing stops some heads’ queries and keys from growing until a few scores dominate every softmax, which can destabilize the training of large models. Normalizing the queries and keys, with a learned scale per dimension, bounds the scores. Qwen3 and Gemma 3 normalize each head separately; OLMo 2 normalizes the whole query and key projections.

For each head’s query \(q\) (and likewise each key), with \(d\) = head_dim and a learned weight \(w\) of size \(d\):

\[\hat{q} = \frac{q}{\sqrt{\tfrac{1}{d}\sum_j q_j^2 + \epsilon}} \odot w\]

The division gives every query the same root mean square, so the length of \(\hat q\) depends on \(w\) and on \(q\)’s direction, not on \(q\)’s size. A score \(\hat q \cdot \hat k\) is then bounded however large \(q\) and \(k\) get. In code, QK-norm is two RMSNorms of size head_dim inside attention, applied to each head after the projection and before RoPE. The other classes only swap in the new attention:

from __future__ import annotations

from max.graph import Dim
from max.nn import ModuleList, RMSNorm
from max.tensor import Tensor

from minillm.attention import Attention
from minillm.config import LlamaConfig
from minillm.layers import apply_rope, rope_cos_sin
from minillm.model import DecoderLayer, LlamaForCausalLM, LlamaModel


class Qwen3Attention(Attention):
    """Llama attention with an RMSNorm on each query and key head."""

    def __init__(self, config: LlamaConfig) -> None:
        super().__init__(config)
        self.q_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)
        self.k_norm = RMSNorm(self.head_dim, eps=config.rms_norm_eps)

    def project(
        self, x: Tensor, start: int | Dim | Tensor
    ) -> tuple[Tensor, Tensor, Tensor]:
        batch, seq, _ = x.shape
        q = self.q_proj(x).reshape([batch, seq, self.num_heads, self.head_dim])
        k = self.k_proj(x).reshape(
            [batch, seq, self.num_kv_heads, self.head_dim]
        )
        v = self.v_proj(x).reshape(
            [batch, seq, self.num_kv_heads, self.head_dim]
        )
        q, k = self.q_norm(q), self.k_norm(k)
        cos, sin = rope_cos_sin(
            self.head_dim, self.rope_theta, start, seq, x.mesh
        )
        return apply_rope(q, cos, sin), apply_rope(k, cos, sin), v


class Qwen3DecoderLayer(DecoderLayer):
    def __init__(self, config: LlamaConfig) -> None:
        super().__init__(config)
        self.self_attn = Qwen3Attention(config)


class Qwen3Model(LlamaModel):
    def __init__(self, config: LlamaConfig) -> None:
        super().__init__(config)
        self.layers = ModuleList(
            [Qwen3DecoderLayer(config) for _ in range(config.num_hidden_layers)]
        )


class Qwen3ForCausalLM(LlamaForCausalLM):
    """Qwen3: a Llama model whose attention normalizes queries and keys."""

    def __init__(self, config: LlamaConfig) -> None:
        super().__init__(config)
        self.model = Qwen3Model(config)

To see what QK-norm guarantees on real activations, run layer 0’s attention on a sentence: its queries and keys, with RoPE, the scores \(q \cdot k / \sqrt{d}\), and their softmax. Then scale the layer’s input up, which scales queries and keys alike, as projection weights that grew during training would. The entropy of a softmax row measures how spread out a query’s attention is: 0 when one key takes all the weight, \(\log n\) when \(n\) keys share it equally.

attn = model.model.layers[0].self_attn
ids = AutoTokenizer(QWEN3)(
    ["Normalizing queries and keys keeps attention scores in a stable range."]
)["input_ids"][0]
seq = len(ids)
h = model.model.layers[0].input_layernorm(
    model.model.embed_tokens(Tensor(np.array([ids]), device=DEVICE))
)
cos, sin = rope_cos_sin(attn.head_dim, attn.rope_theta, 0, seq, DEVICE)
causal = np.triu(np.full((seq, seq), -np.inf), 1)


def softmax(z: np.ndarray) -> np.ndarray:
    e = np.exp(z.astype(np.float64) - z.max(-1, keepdims=True))
    return e / e.sum(-1, keepdims=True)


def entropy_per_head(scale: float, qk_norm: bool) -> np.ndarray:
    """Mean attention entropy of each query head, in nats."""
    x = h * scale
    q = attn.q_proj(x).reshape([1, seq, attn.num_heads, attn.head_dim])
    k = attn.k_proj(x).reshape([1, seq, attn.num_kv_heads, attn.head_dim])
    if qk_norm:
        q, k = attn.q_norm(q), attn.k_norm(k)
    q = apply_rope(q, cos, sin).to_numpy()[0]
    k = apply_rope(k, cos, sin).to_numpy()[0]
    k = np.repeat(k, attn.num_heads // attn.num_kv_heads, axis=1)
    scores = np.einsum("qhd,khd->hqk", q, k) / np.sqrt(attn.head_dim)
    p = softmax(scores + causal)
    # Position 0 sees only itself, so its entropy is always 0.
    return -(p * np.log(p + 1e-30)).sum(-1)[:, 1:].mean(-1)

Move the slider. Without the norm (orange), the attention depends on the scale. Scaling the input by 10 makes queries and keys 10 times longer and the scores 100 times larger, and the softmax collapses: the orange bars fall close to 0, so each query attends to almost a single key. At x1 the orange bars sit higher than the blue ones, because Qwen3’s raw queries and keys are small; the trained model always normalizes them. The blue bars don’t move at all. After q_norm and k_norm, a query’s or key’s length depends only on its direction and the learned per-dimension scale, so no input can make a score blow up.

Verify it

Compare with Hugging Face’s PyTorch Qwen3 on a few prompts, using the metrics from Section 4.2:

tokenizer = AutoTokenizer(QWEN3)
reference = AutoModelForCausalLM.from_pretrained(
    QWEN3, torch_dtype=torch.float32
).eval()


prompts = {
    "english": "The capital of France is",
    "code": "def add(a, b):\n    return",
    "french": "Le chat est assis sur",
}
for name, text in prompts.items():
    ids = tokenizer([text])["input_ids"][0]
    ours = compiled(Tensor(np.array([ids]), device=DEVICE)).to_numpy()[0]
    with torch.no_grad():
        theirs = reference(torch.tensor([ids])).logits[0].numpy()
    r = compare_outputs(ours, theirs, atol=1e-3, rtol=1e-3)
    p, q = softmax(theirs), softmax(ours)
    kl = float((p * (np.log(p + 1e-30) - np.log(q + 1e-30))).sum(-1).mean())
    top1 = (ours.argmax(-1) == theirs.argmax(-1)).mean()
    print(
        f"{name:8} max err {r.max_abs_err:.1e}  KL {kl:.1e}  top-1 {top1:.0%}"
    )
    assert top1 >= 0.99 and kl < 1e-6

def next_logits(ids: list[int]) -> Tensor:
    return compiled(Tensor(np.array([ids]), device=DEVICE))[0, -1]


prompt = tokenizer(["The three primary colors are"])["input_ids"][0]
print(
    tokenizer.decode(prompt + generate(next_logits, prompt, 24, temperature=0))
)

That is the whole bring-up: about 40 lines of model code for a new architecture, checked against the reference to rounding error. MAX’s own Qwen3 implementation serves the same model with a paged KV cache and continuous batching, the techniques that Chapter 5 builds:

max serve --model Qwen/Qwen3-0.6B --quantization-encoding float32 --no-prefer-module-v3

--no-prefer-module-v3 selects MAX’s text-generation implementation of Qwen3. By default MAX prefers an architecture’s module-based implementation (Section 7.1 explains this preference), and while the only module-based one registered under Qwen3’s architecture name is the embedding model, max serve picks it for this checkpoint and fails to start.

Qwen3 is also a reasoning model: by default it thinks step by step inside <think> tags before it answers, which costs tokens and improves answers to hard questions. Its chat template has an enable_thinking switch that turns this off. The handbook’s choosing the right model page discusses that trade-off.
