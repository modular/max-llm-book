7.4 Modular’s cloud

Everything in this book ran on your own machine: models of up to 0.6B parameters, with multi-device meshes simulated on a CPU. Serving state-of-the-art open models to real traffic takes more: the largest models span many GPUs, capacity has to follow demand, and someone has to respond when a node fails. Modular’s cloud is an inference service that runs those models on MAX, the framework you used in this book. This last section points your client code at it by changing the base URL, the API key, and the model name.

import os
import subprocess
import time
import urllib.request

from openai import OpenAI

from minillm.config import MODEL_ID

Two ways to call a hosted model

Modular’s cloud serves popular open models behind the same OpenAI-compatible API that the earlier sections of this chapter used:

  • Shared endpoints are billed per token, and their capacity scales automatically, down to zero when idle.
  • Dedicated endpoints reserve GPUs for you and are billed per minute, for consistent latency and guaranteed throughput.

The pricing page compares them.

The same client, a different URL

Every server in Chapter 7 spoke the OpenAI API, and so do Modular’s endpoints. Here is the client from Section 7.1 against a local server again:

server = subprocess.Popen(
    [
        "max",
        "serve",
        "--model",
        MODEL_ID,
        "--port",
        "8000",
        "--quantization-encoding",
        "float32",
    ],
    stdout=subprocess.DEVNULL,
    stderr=subprocess.DEVNULL,
)
while True:
    try:
        urllib.request.urlopen("http://localhost:8000/health")
        break
    except OSError:
        if server.poll() is not None:
            raise RuntimeError(
                "max serve exited; run it in a terminal to see why"
            )
        time.sleep(1)


def ask(client: OpenAI, model: str, question: str) -> str:
    completion = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": question}],
        max_tokens=60,
    )
    return completion.choices[0].message.content


local = OpenAI(base_url="http://localhost:8000/v1", api_key="unused")
print(ask(local, MODEL_ID, "What is the capital of France?"))
server.terminate()
_ = server.wait()

The capital city of France is Paris. It is located in the northern part of the country, in the eastern part of the Po River, and is the cultural heart of France. Paris is known for its rich history, iconic landmarks, and stunning architecture.

To call a hosted model instead:

  1. Sign up at console.modular.com.
  2. Create an API key with model access on the API keys page, and set it as the MODULAR_API_KEY environment variable. In Colab, add it as a secret and copy it into os.environ.
  3. Pick a model on the endpoints page, and set its model ID as MODULAR_MODEL.

Only the base URL, the key, and the model name change. The cell skips the request when no key is set:

api_key = os.environ.get("MODULAR_API_KEY")
if api_key is None:
    print("Set MODULAR_API_KEY and MODULAR_MODEL to call a hosted model.")
else:
    hosted = OpenAI(base_url="https://api.modular.com/v1", api_key=api_key)
    print(
        ask(
            hosted,
            os.environ["MODULAR_MODEL"],
            "What is the capital of France?",
        )
    )

Set MODULAR_API_KEY and MODULAR_MODEL to call a hosted model.

The API is the same, so code written against it, such as the structured output in Section 7.3, works with hosted models that support the feature. max benchmark measures a hosted endpoint as it measured your local server. The mcloud backend reads the key from OPENAI_API_KEY, and because a hosted endpoint manages its own cache, the command skips flushing it:

OPENAI_API_KEY=$MODULAR_API_KEY max benchmark --backend mcloud \
  --base-url https://api.modular.com --endpoint /v1/chat/completions \
  --no-flush-prefix-cache --model $MODULAR_MODEL \
  --dataset-name random --random-input-len 128 --random-output-len 32 \
  --num-prompts 32 --max-concurrency 8

Before you choose between shared and dedicated endpoints, benchmark with your real prompt and answer lengths; the latency targets from Section 7.2 apply unchanged. The handbook’s choosing the right model and calculating GPU memory pages help you choose a model and estimate the GPUs it needs.
